# Feature 01 — Core Messaging

## Goal
Make the existing single-text-message flow production-ready and add the missing basic message types needed for a usable WhatsApp API gateway.

## Scope

- Send a text message to a single JID (personal or group).
- Validate the target JID format.
- Return a message ID and initial delivery status.
- Surface send errors clearly to the API consumer.
- Group support via `@g.us` detection (already partially supported).

## API / UI

### Backend endpoints

```http
POST /api/chats/{jid}/messages
Content-Type: application/json

{
  "body": "Hello!",
  "type": "text"
}
```

Response:

```json
{
  "id": "msg_uuid",
  "jid": "12345@s.whatsapp.net",
  "body": "Hello!",
  "status": "pending",
  "created_at": "2026-08-19T12:00:00Z"
}
```

### Frontend

- Composer in chat window supports plain text.
- Show send errors inline (e.g., "not connected", "invalid number").

## Data model changes

- `whatsapp-api-types::Message` gains:
  - `id: String` (stable UUID generated by server)
  - `status: MessageStatus` (`pending`, `sent`, `delivered`, `read`, `failed`)
  - `direction: MessageDirection` (`outgoing` / `incoming`)
  - `error: Option<String>`

## Dependencies

- `whatsapp-rust` send text API.
- Existing `EngineService::send_text`.

## Implementation notes

- Generate message ID before calling the engine so status updates can be correlated later.
- Track outgoing messages in the in-memory registry (capped at 1000 per chat) and broadcast `WsEvent::MessageStatusUpdate` when receipts arrive.
- Keep the engine as the only crate that imports `whatsapp-rust`.

## Acceptance criteria

- [ ] `POST /api/chats/{jid}/messages` returns a stable message ID.
- [ ] Invalid JID returns `400 Bad Request` with clear error.
- [ ] Sending while disconnected returns `503 Service Unavailable`.
- [ ] Outgoing message appears in the chat history immediately.
- [ ] Delivery status updates propagate over `/ws`.
- [ ] `cargo build --workspace` and `cargo clippy --workspace` pass.
